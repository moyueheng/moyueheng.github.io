我们不是缺信息，而是信息太多。真正稀缺的不是资料，而是注意力、判断和持续推进。

大量内容进来之后，常常停在收藏夹、聊天记录、浏览器标签页和消息里，最后没有进入项目，也没有变成输出。

我做 MyhronOS，就是想解决一个很具体的问题：怎么把每天流进来的信息，稳定地变成项目推进、研究结论和可复用的知识。

## 从输入到输出

```text
输入(Input)
  x.com / Newsletter / 论文 / IM / 网页 / 想法
        ↓
处理(Process)
  00_Inbox -> 10_Daily -> 20_Project
        ↓
沉淀(Sediment)
  30_Research / 40_Wiki / 50_Resources
        ↓
输出(Output)
  分享 / 文章 / 决策 / 交付
```

这个系统不是围绕「收藏更多」设计，而是围绕「最后产出什么」设计。

## 两层知识

MyhronOS 里有两层内容：

- `raw/` 与 `wiki/` 是 AI 编译层。AI 负责抓取、整理、初步编译和建立索引。
- `30_Research/`、`40_Wiki/`、`20_Project/` 是人类沉淀层。判断、取舍和观点由我自己完成。

AI 编译层可以处理海量输入，但我不会把它直接当成自己的知识。只有经过筛选、改写和链接的内容，才会进入人类沉淀层。

```text
外部资料
  ↓ AI 抓取 / 编译 / 初步整理
raw/ + wiki/
  ↓ 人类判断 / 取舍 / 建立连接
40_Wiki / 20_Project / 10_Daily
  ↓
项目 / 研究 / 分享 / 决策
```

## 三条原则

### AI 负责处理信息，人类负责形成观点

AI 可以做搬运、整理和初稿，但不能代替判断。越是在 AI 可以大量生成内容的时候，人越需要锻炼自己的判断能力。

### 输入必须服务于输出

如果一条信息最终不服务于项目、研究、写作、分享或决策，它大概率只是堆积。

### 知识层必须自己编辑

`40_Wiki/` 和 `20_Project/` 的大部分内容由我修改和确认。可以没有标签，但必须进入已有的链接网络。

## Obsidian 更像健脑房

我不把 Obsidian 当成仓库，而更像「健脑房」和工作台。

构建第二大脑的目的，是强化第一大脑，而不是把思考外包给一个越来越大的资料库。

```text
水源   -> 外部世界的信息流
水渠   -> Inbox 和处理流程
水库   -> 结构化沉淀
发电站 -> 项目、分享、决策、输出
```

## 工作流

系统通过一组 skill 把流程固定下来：

- `/life-start-my-day`：回顾昨天、检查活跃项目、生成今天的行动上下文。
- `/life-kickoff`：把想法拆成有边界、有验收标准的项目。
- `/life-research`：围绕一个问题做研究，并沉淀成研究资料或项目输入。
- `/learn-llm-wiki`：把外部文章、论文和推文编译成结构化知识。

工具会变，模型会变，但「输入 -> 处理 -> 沉淀 -> 输出」这条链路是稳定的。

## 边界

这套系统不适合所有人，也不应该追求全自动。

它的前提是：你愿意持续写、持续链接、持续判断。AI 可以降低整理成本，但不能替你决定什么值得留下。
